Giving the CEOS Database a day job

6 November 2026 · George Dyke · aeo-forum-2026 ceos-database earth-observation

A companion to a talk at the Advancing Earth Observation Forum 2026 in Hobart.

The Earth observation value chain starts with measurement upstream, and these measurements produce data and products that support applications and decisions downstream. The CEOS EO Capabilities Explorer seeks to help people explore connections.

The Explorer builds on the CEOS Missions, Instruments and Measurements (MIM) Database, via its open API. This API is part of giving the Database a “day job”, moving towards putting a longstanding reference to work.

The Explorer and API are in beta, and you can find out more on the about, user guide and feature reference pages.

Where it comes from

ESA’s support for the CEOS Earth Observation Handbook stretches back to the 1990s, with the Database being added in 2007.

2026 extension work has added the API and Explorer as pilot activities under Australia’s CEOS Chair year, supported by Geoscience Australia. The familiar CEOS Database remains in place, while the Explorer and API offer new ways to use its information.

Browse the observing system

  • Missions, instruments and measurements. Search the mission index, then follow the links to instruments and their measurements. The mission, instrument and measurement guides explain what each record contains.
  • Constellations and commercial missions. Coverage now includes selected commercial civil EO systems, including constellation records which link programs to their spacecraft. Commercial records continue to be added to fill out the collection.
  • The bigger picture. At a Glance gives an overview, the launch tracker looks ahead, and continuity views show anticipated measurement coverage over time.

Look more closely

  • Identifiers. Canonical identifiers help recognise records which may have different names or aliases, and they can be browsed in the identifier table. This information can also be accessed via the API.
  • Possible jobs. A tentative mapping links the proposed identifier classes, database records, and STAC common metadata fields.
  • Technical detail for CEOS-ARD. The SAR parameters pilot adds frequency, bandwidth, polarisation, and imaging-mode details such as resolution, swath and incidence range, for example with PALSAR-2. These records can help inform data production and CEOS-ARD work.
  • Quality reports. Mission and product pages link to selected USGS and ESA data quality assessments.
  • Satellite visuals. The satellite-visuals collection brings together spacecraft illustrations, silhouettes and photographs to help communicate the physical aspects of the observing system. The imagery guide explains the approach.

Make your own view

  • Custom timelines. Create your own timeline, choosing missions individually or by agency, instrument type, measurement or theme, then add your own assumptions and annotations. Build a timeline and share it by URL, export, or save and load JSON. See the timeline guide.
  • Instrument builder. Describe a proposed sensor or edit a copy of an existing record, then view it on the spectrum and share it by link or JSON. The builder is a Preview feature, with details in the custom-instrument guide.

These tools work client-side and retain a working copy in your browser. These are labelled user-defined views, not changes to the CEOS Database records.

Connect capabilities to products and uses

  • Product records. Browse products and their links to instruments, provider documentation, data access and CEOS-ARD information where available. The collection is still growing, and the product guide explains the sources, and linked assessments establish each product’s scope and status.
  • Thematic views. Themes and timelines organise observing capabilities around user needs and applications, including case-study context from the EO Handbook. The thematic guide explains how to use them.

Explore

  • Spectrum Explorer. Browse the electromagnetic spectrum and see which instruments use each region or band. Open the Spectrum Explorer or read the guide.
  • Spectrum crosswalk. Compare capabilities within a band across missions and agencies. This is a pilot tool, described in the crosswalk guide.
  • An initial chatbot. Ask a question about the holdings in plain language and follow the database records cited in the answer. The assistant is a Preview feature, so check those records before relying on its response.

Use the API

  • Access the same information. The read-only API serves the same published snapshot as the Explorer, for use in scripts, spreadsheets and other applications. No sign-up is needed, free keys are available for heavier use, and the API endpoints are still evolving.
  • Try a notebook. The worked example, also available in Colab, shows how to retrieve records, resolve a nickname and check the registry edition. Use the interactive reference for the full API details.
  • CEOS-ARD experiments. Separate notebooks explore how the API could support assessment workflows. The notebook guide describes these pilots; they are not an automated assessment service.

Where next?

We want to make it easier to move between upstream observing systems, data and products, and downstream applications – and back again. Product links and thematic views are a start; a complete provenance chain and database write access are future work.
